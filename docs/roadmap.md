# 开发路线图 · 智汇于庄

> 本路线图按"先底座、再闭环、后亮眼"的顺序推进：先打通一条最小业务闭环，
> 再叠加高并发工程能力与 AI 能力，最后做公域渠道与答辩演示。

## 阶段总览

```text
阶段 0  项目骨架与基础设施        ── 当前所处阶段
阶段 1  最小业务闭环（单渠道下单）
阶段 2  高并发工程能力（削峰/防超卖）
阶段 3  AI 能力（RAG + 多智能体）
阶段 4  M 端与 C 端接入、数据大屏
阶段 5  公域渠道与答辩打磨
```

---

## 阶段 0 · 项目骨架与基础设施

**目标：** 仓库结构清晰、基础设施可一键拉起、文档齐备。

- [x] 重写 README（三端鼎立 + 工业级底座愿景）
- [x] 总体架构文档 `docs/architecture.md`
- [x] 骨架目录（backend / ai-service / web / h5 / mobile）
- [x] Docker Compose（PostgreSQL pgvector + Redis + Nginx 网关）
- [x] 根级 `.env.example` / `.gitignore` / `Makefile`
- [ ] 初始化 git 仓库并建立首次提交基线

**完成标准：** `make infra-up` 后三件套健康运行；目录/文档可作为团队协作基线。

---

## 阶段 1 · 最小业务闭环（backend + B 端最小可用）

**目标：** 打通"商品上架 → 下单 → 扣库存 → 订单查询"的最小闭环。

- [ ] `backend/` Spring Boot 工程骨架（多模块、统一响应、异常处理）
- [ ] 领域模型建表：租户、用户、商品/SKU、订单、订单项、库存
- [ ] Tenant ID 多租户行级隔离基础设施
- [ ] 商品 CRUD + 库存初始化（JPA/MyBatis 选型）
- [ ] 下单接口（事务内扣库存，单库直连，先不做削峰）
- [ ] JWT 认证 + 租户上下文
- [ ] `web/` B 端：登录、商品管理、订单列表
- [ ] OpenAPI 文档（Springdoc）

**完成标准：** Postman 可完成 用户登录 → 创建商品 → 下单 → 扣减库存的闭环。

---

## 阶段 2 · 高并发工程能力

**目标：** 支撑直播带货洪峰，解决超卖与可靠性问题。

- [ ] Redis 接入：缓存（商品/库存）、分布式锁、会话
- [ ] Redis Streams：下单削峰生产者 + 消费者（异步落库）
- [ ] CAS 乐观锁扣库存（`stock >= n` 条件更新）与失败重试
- [ ] Outbox 发件箱：订单事件与业务同事务写发件箱，后台可靠投递
- [ ] 幂等与渠道流水号去重
- [ ] 压测脚本（如 `wrk`/`JMeter`）与调优
- [ ] 渠道抽象 `OrderSource` + 适配器骨架（先支持 H5，预留抖音/快手）

**完成标准：** 压测下无超卖、无重复单；演示"瞬时洪峰 → 平滑落库"的大屏/日志曲线。

---

## 阶段 3 · AI 能力（ai-service）

**目标：** RAG 防幻觉问答 + 多智能体营销内容生成。

- [ ] `ai-service/` FastAPI 工程骨架与配置
- [ ] pgvector 启用 + 知识库表（文档/切片/向量）
- [ ] PDF 解析 → 结构化切片 → Embedding 入库（ingest 管线）
- [ ] 双路召回（向量 + 关键词）与重排
- [ ] DeepSeek 接入 + 强约束防幻觉 Prompt + 引用溯源
- [ ] 语音转写接口（预留 ASR 适配）
- [ ] 多智能体编排（热点/文案/合规质检/定价）
- [ ] 人工审批流（对接 B 端策略审批页面）
- [ ] 接入真实"鹿邑/于庄"惠农政策与病虫害防治样例文档

**完成标准：** 问答可溯源、内容合规可过审；Demo 语音提问于庄小麦/药材种植问题可得到依据手册的答复。

---

## 阶段 4 · M 端与 C 端接入、数据大屏

- [ ] `h5/` C 端 H5：商品列表、下单、抢购、订单跟踪（复用 backend API）
- [ ] `mobile/` Flutter：登录、扫码发货、离线缓存、语音提问农技
- [ ] `web/` 数据大屏：订单/库存/渠道/销售多维可视化
- [ ] 微信授权（openid）接入 H5 私域下单
- [ ] 后端统一订单聚合 API（H5/App 共用）

**完成标准：** 三端均可访问同一后端；移动端弱网可用；大屏数据实时刷新。

---

## 阶段 5 · 公域渠道与答辩打磨

- [ ] 抖音/快手 OpenAPI 沙箱对接（直播商品与订单回流）
- [ ] B2B 大宗集采门户（报价、批量下单、合同/批次）
- [ ] 多租户演示数据脚本（于庄合作社 + 子账号）
- [ ] Docker Compose 全栈一键拉起（backend/ai/web/h5/mobile 编排）
- [ ] 演示视频脚本与 PPT 素材整理（含压测曲线、RAG 溯源截图）

**完成标准：** 全栈 `docker compose up` 一键演示；答辩材料齐全。
