# 前端体验提升进度

## 基线审查（2026-09-06）

### 本轮完成内容

- 盘点两套可运行前端：`web/`（Next.js B 端）与 `h5/`（Vite React C 端）。
- 覆盖 B 端 `/b/dashboard`、`/b/knowledge`、`/b/agents`、`/b/orders`，以及 H5 商品、结算抽屉、表单校验、AI 问答抽屉。
- 在 1440×1000、768×900、390×844 三组视口下完成浏览器视觉检查与横向溢出检测。
- 执行两端生产构建，均通过；确认仓库当前没有 lint、独立 typecheck、test 脚本和前端测试。

### 主要页面与流程

- B 端：根路由跳转 → 治理大盘；全局租户切换与服务链路状态；知识库检索与 RAG 问答；营销需求 → 多 Agent 生成 → 合规报告 → 人工审批；订单筛选 → 履约状态查看 → 就绪单出库。
- H5：商品加载/刷新 → 商品浏览 → 结算表单 → 下单反馈 → 成功弹窗；悬浮入口 → 农技问答 → 引用溯源。
- 当前仓库没有登录、注册、设置、退出或删除业务页面；本次不凭空新增不存在的业务流程。

| 优先级 | 问题 | 影响 | 修改方案 |
| --- | --- | --- | --- |
| P0 | B 端侧栏固定 228px，390px 内容区仅 162px；知识库与订单有 7–10 个控件落在可视区外 | 手机端不可用，平板端信息密度失控 | 重构响应式 AppShell：桌面侧栏、平板紧凑导航、手机抽屉菜单；统一内容宽度和页面边距 |
| P0 | TopBar 在首屏直接渲染 `new Date()`，控制台稳定出现 hydration mismatch，并导致整棵根节点改为客户端渲染 | 首屏闪烁、性能和稳定性下降 | 服务端输出稳定占位，挂载后再启动时钟；加入回归检查 |
| P0 | 弹窗/抽屉缺少 `role=dialog`、`aria-modal`、焦点圈定、Esc 关闭与焦点归还 | 键盘和辅助技术用户难以完成流程 | 建立统一 Dialog/Drawer 行为层，补齐语义、焦点和滚动锁定 |
| P1 | 页面由大量同质白卡片拼接，标题普遍偏小，演示/技术说明抢占视觉注意力 | 模板感明显，业务重点不突出 | 建立 PageHeader、关键指标、内容面板三层结构；弱化技术注释，突出主任务和关键数据 |
| P1 | 色值、圆角、阴影、控件高度和 10–13px 字号散落在页面类名中 | 风格难维护，跨页不一致 | 用 CSS 变量与共享原语统一颜色、排版、间距、圆角、阴影、状态和动效 |
| P1 | 按钮只有零散 hover/active，绝大多数没有清晰 focus-visible；租户菜单缺少 expanded/menu 语义 | 操作层级和键盘反馈不清楚 | 建立 primary/secondary/ghost/danger 按钮及完整状态；补齐菜单键盘语义 |
| P1 | 知识库与订单在窄屏仅横向表格，筛选入口还会隐藏 | 平板/手机查找与操作成本高 | 桌面保留表格，手机切换为信息卡列表；筛选与主要操作始终可达 |
| P1 | Dashboard/Knowledge/Orders 主要使用静态演示数据，缺少统一的页面级 loading/error/skeleton；订单出库无成功反馈 | 异步行为表达不一致，操作结果不明确 | 引入统一 StateView、Skeleton、Toast；为真实请求和本地状态迁移补齐反馈 |
| P1 | Agent 表单错误只显示在卡片底部，字段不聚焦、无字段级说明；渠道按钮不具备 checkbox 语义 | 修正错误慢，表单可访问性弱 | 使用 Field 组件、内联错误、字符/条数提示、aria-invalid 与字段聚焦 |
| P1 | H5 商品图片指向不可访问的 `.example` 域名，失败后用超大 emoji 兜底 | 首屏廉价且违背正式图标要求 | 改为项目内可控的产品视觉资产与正式兜底插画，不依赖远程占位域名 |
| P2 | H5 在桌面始终只有 430px 单列，背景大面积空白；多个 CTA、Hero 同时使用高饱和渐变和较重阴影 | 桌面展示缺少作品集完成度，视觉噪音偏高 | 桌面增加品牌/产地叙事侧栏，移动端保持转化单列；收敛渐变和阴影 |
| P2 | H5 表单仅 Toast 报错，无字段内错误；对话层打开后未稳定聚焦，Esc 无效 | 用户容易遗漏错误，键盘流程中断 | 增加字段级错误、错误摘要、自动聚焦；统一移动抽屉行为 |
| P2 | 全局缺少 `prefers-reduced-motion`；H5 禁止页面缩放 | 动效敏感与低视力用户体验不佳 | 提供 reduced-motion 兜底，移除 `user-scalable=no`/`maximum-scale=1` |
| P2 | 公共页面头、指标块、控件样式重复实现；B/H5 内部状态视图不统一 | 修改成本高，容易继续分叉 | 分别在两个应用内收敛可复用原语；跨应用只共享设计规范，不强行共享运行时代码 |
| P2 | B 端品牌短名“数字于庄”与主标题“智汇于庄”不一致，侧栏展示网关与端口等开发信息 | 品牌记忆混乱，不像面向真实用户的成品 | 统一品牌命名；技术信息移入低优先级的“演示环境”信息区 |

### 视觉检查结果

- 1440px：四个 B 端页面可操作，但层级偏平、卡片同质、短页面存在无意义空白；H5 居中单列、两侧空白过大。
- 768px：B 端侧栏占 29.7% 宽度，知识库和订单各有 6 个控件超出可视区域；H5 可用但仍按手机单列呈现。
- 390px：B 端所有页面不可用，知识库与订单分别有 7 和 10 个控件在可视区域外；H5 无页面级横向溢出，结算与问答层视觉完整。
- 控制台：B 端时钟造成 hydration error；H5 未发现自身 hydration 问题。

### 测试结果

- `web/npm run build`：通过；Next.js 明确跳过 lint，类型检查通过。
- `h5/npm run build`：通过；`tsc --noEmit` 与 Vite 构建通过。
- lint / test：当前无对应脚本，列入后续质量基建。
